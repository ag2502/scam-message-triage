    Where it misses

    Conversation starters like "sorry, wrong number... do you invest?" carry no scam content yet. Single-message triage can't see where a chat is heading.

    Where it over-warns

    Outgoing bank-transfer confirmations still score too high in held-out tests. That is the main source of false alarms.

    What would fix it

    Consented, labelled messages that people forward to the bot. The data is synthetic today, and the dataset card says so.

    README.md

    # Scam Triage

    An explainable scam checker for instant-payment fraud: Pix, UPI, Zelle, SPEI, wallets, gift cards and crypto.

    ## How it works

    24 readable warning signals plus word and character n-grams feed two small linear models: one scores risk, one names the scam type. Thresholds are set for 1% and 5% false alarms.

    ## Honest limits

    Trained on synthetic English data plus real legitimate SMS. It misses conversation-starter scams and still over-warns on some bank-transfer receipts.

      (・_・?) Reasonable questions

      Is my message sent anywhere?

      Not on this page. The model downloads once and runs in your browser, and nothing you paste leaves your device. The WhatsApp bot does receive the messages you forward to it, and it never logs their text.

      Can it be wrong?

      Yes. On the blind test set it caught about 87% of scams at the high level with no false alarms, and 93% at the medium level. Treat it as a second opinion, then check through a channel you already trust.

      Which languages and countries does it support?

      English today, with examples from Brazil, India, the US, the UK, Mexico and Europe. Brazilian Portuguese is next, then Spanish. Word lists and examples live in per-language modules, so adding a language changes no code.

      Is the WhatsApp bot live?

      The code is finished and tested: webhook, signature checks, retries and quoted replies. Running it on a public number needs a Meta business account and verification. Until then, you can host it yourself with the steps in the README.

      How would a bank or fintech use it?

      Call the API from a "check before you pay" step, or show the warning when a new payee is added. The response includes a ready-to-show reply, and the model is small enough to run inside the app.

      Why not just ask a chatbot?

      A small linear model is fast, free to run, works offline and explains itself by pointing at exact phrases. Its false-alarm rate is measured and fixed. A language model is a possible future layer, kept only if it beats this one when false alarms must stay low.

      Can scammers learn to beat it?

      Some will try. Character fragments make simple tricks such as typos, extra spaces and look-alike letters less effective, and the hard requests stay the same whatever the wording: send money, share a code, move your savings.

      Is it free and open source?

      Yes. The code is MIT-licensed and the dataset is CC BY 4.0. Everything is on GitHub, including the evaluation history.
